## **1. 도입 배경 및 과제 (Background & Problem)**

금융, 통신, 항공 등 **56개 주요 대형 고객사**를 대상으로 대량의 고객 알림 및 청구 발송 솔루션을 제공하는 B2B 비즈니스 환경에서는 시스템 장애나 버그가 고객사의 비즈니스 중단 및 대외 신뢰도 실추와 직결됩니다.

<a id="핵심-해결-과제"></a>

### **🎯 핵심 해결 과제**

1. **신속한 무중단 기술 지원 체계 구축**:
- 업무 외 시간에도 발생하는 장애 및 레거시 마이그레이션 결함을 빠르게 격리/해소할 수 있는 표준화된 CS 파이프라인 부재.

1. **비개발 대응 인력의 기술적 자생력 확보**:
- 리눅스 서버 접속 및 로그 분석 권한이 없는 1차 CS 대응 인력의 에스컬레이션 의존도로 인해 개발팀의 유지보수 부하 급증.

1. **가상화(VMware ➔ Docker/K8s) 전환에 따른 기술 격차 해소**:
- 고객사 및 사내 비개발 부서의 YAML 설정 및 컨테이너 패키징 지식 허들로 인한 잦은 인프라 지원 요청 발생.

## **2. Part 1: B2B 기술 지원 데이터 자산화 & 쉘 스크립트 툴킷 배포**

<a id="1-jira-notion-연동을-통한-장애-추적-데이터-자산화"></a>

### **① Jira ↔ Notion 연동을 통한 장애 추적 데이터 자산화**

- 유선/이메일 기반의 휘발성 CS 대응을 탈피하고, **Jira 백로그와 Notion Wiki를 양방향 연동**.
- 고객사별 이슈 인입부터 재현 절차, 로그 분석, 핫픽스 커밋, 고객 안내 내역까지 엔드투엔드(End-to-End) 히스토리를 데이터베이스화하여 동일 장애 재발 시 즉각 대처 가능한 지식 베이스 구축.

<NotionDivider />

<a id="2-비전공-cs-인력을-위한-linux-트러블슈팅-쉘-툴킷-배포"></a>

### **② 비전공 CS 인력을 위한 Linux 트러블슈팅 쉘 툴킷 배포**

코드를 직접 수정할 수 없는 1차 CS 인력도 터미널에서 즉시 1차 원인을 진단할 수 있도록 **원클릭 진단 쉘 스크립트(Shell Script) 세트**를 제작하여 배포했다.


```bash
#!/bin/bash
# ==============================================================================
# B2B Mail Server Health & Policy Diagnostic Script (CS 1차 대응용)
# ==============================================================================

echo "=== [1] 이메일 서버 보안 정책 및 포트 바인딩 확인 ==="
netstat -tulpn | grep -E ':(25|465|587|8080)\b'

echo "=== [2] 최근 1시간 이메일 응답 코드(SMTP Response Code) 통계 집계 ==="
# 로그에서 4xx(일시 오류), 5xx(영구 실패) 코드를 그룹핑하여 카운트
awk '{for(i=1;i<=NF;i++) if($i ~ /^[45][0-9]{2}$/) print $i}' /var/log/mail/delivery.log | sort | uniq -c | sort -nr

echo "=== [3] 대상 메일 서버 SSL/TLS 인증서 만료일 점검 ==="
TARGET_HOST="mail.customer-enterprise.com"
echo | openssl s_client -servername ${TARGET_HOST} -connect ${TARGET_HOST}:465 2>/dev/null | openssl x509 -noout -dates

echo "=== 진단 완료: 결과 로그를 Jira 이슈 티켓에 첨부하세요. ==="
```

## **3. Part 2: 가상화 컨테이너(Docker/K8s) 배포 지원 및 패키징 체계화**

<a id="1-사내-포털-ui-옵션-yaml-매핑-가이드라인-수립"></a>

### **① 사내 포털 UI 옵션 ↔ YAML 매핑 가이드라인 수립**

- 사내 포털의 배포 UI 설정값(메모리 리밋, 환경 변수, 포트 바인딩 등)이 백엔드에서 실제 `deployment.yaml` 및 `docker-compose.yml`의 어떤 항목으로 치환되는지 시각적 매핑 테이블 제공.
- 비개발 직군도 설정 오류 없이 안전하게 파라미터를 조정할 수 있는 가이드라인 자산화.
<a id="2-vmware-vm-컨테이너-커스텀-빌드-스크립트-지원"></a>

### **② VMware VM ➔ 컨테이너 커스텀 빌드 스크립트 지원**

- Docker Hub 공식 레지스트리에서 지원하지 않는 특수 레거시 온프레미스 환경을 위해, 기존 VMware VM 리소스를 추출하여 컨테이너화하는 `build.script` 및 커스텀 `entrypoint.sh` 제작 지원.
- **배포 지원 성과**:
- 고객사 빅데이터 테스트 전용 커스텀 이미지 **2종** 배포 완료
- Web Build 전용 커스텀 이미지 **2종** 안정적 제공
- 솔루션 기본 탑재 백엔드 컨테이너 이미지 **12종**에 대한 구동 원리 및 Compose 패키징 문서화 완성

## **4. Part 3: 지속 가능한 B2B 유지보수 및 고객 엔지니어링 철학**


```text
[B2B 고객 엔지니어링 3대 핵심 프레임워크]
1. 고객사 눈높이 맞춤 소통 (비개발자용 요약 다이어그램 vs 엔지니어용 상세 기술 명세)
2. 정기점검 기반 실환경 프로파일링 (EOS/EOL 선제 파악 & 영업 제안 연계)
3. 엔터프라이즈 기본 템플릿 제공 (메시징 템플릿 & DevOps 베이스 이미지 락인)
```

<a id="1-고객사-눈높이에-맞춘-다층-문서화-multi-tier-documentation"></a>

### **① 고객사 눈높이에 맞춘 다층 문서화 (Multi-tier Documentation)**

- **비개발 담당자용**: 복잡한 아키텍처를 추상화한 **한눈에 보는 요약 다이어그램** 및 비즈니스 영향도 중심 설명 제공 (보고 체계 편의성 지원).
- **개발자/인프라 담당자용**: 시스템 파라미터, 네트워크 패킷 덤프, 스택 트레이스 기반의 **상세 기술 보고서** 분리 제공.
<a id="2-정기점검-기반-고객사-환경-프로파일링-사전-패치-제안"></a>

### **② 정기점검 기반 고객사 환경 프로파일링 & 사전 패치 제안**

- 정기점검 시 고객사 런타임 환경(OS, JDK, WAS, DB 버전)을 체계적으로 전수 조사하여 사내 DB에 프로파일링.
- **EOS(End of Support) / EOL(End of Life)** 임박 제품을 사전에 고객사에 안내하여 장애 위험 사전 제거.
- 메이저/마이너 패치 가능 여부를 선제 검토하고, 영업팀에 공유하여 단순 유지보수를 넘어 **신규 사업/업그레이드 제안의 백그라운드 데이터로 활용** (보안 및 라이선스 컴플라이언스 준수).
<a id="3-제품-기본-템플릿starter-template-제공을-통한-고객-락인lock-in"></a>

### **③ 제품 기본 템플릿(Starter Template) 제공을 통한 고객 락인(Lock-in)**

- **메시징 솔루션**: 즉시 적용 가능한 표준 메시지/알림 템플릿 및 가이드라인 기본 탑재.
- **DevOps 관리 솔루션**: VM 컨테이너화 요구에 맞춰 즉시 기동 가능한 커스텀 베이스 이미지 및 `entrypoint.sh` 표준 템플릿 번들링 제공.
