## 핵심 요약

**객체지향 언어(OOP: Object-Oriented Programming)**는 데이터(상태)와 기능(행위)을 하나로 묶은 **'객체(Object)'**들을 조립하여 프로그램을 구축하는 프로그래밍 패러다임이다.

**Java**는 클래스(Class)를 최우선 단위로 설계하고 캡슐화, 상속, 다형성, 추상화를 언어 차원에서 강제 및 보장하므로 대표적인 객체지향 언어다.


<NotionDivider />

<a id="1-객체지향-언어oop란-무엇인가"></a>

## 1. 객체지향 언어(OOP)란 무엇인가?

프로그램을 단순한 명령어의 순차적 실행이 아니라, **현실 세계의 개념을 모델링한 '객체(Object)'들의 상호작용**으로 바라보는 방식이다.


```text
[객체 (Object)] = 상태 (State / 필드) + 행위 (Behavior / 메서드)
```

<a id="oop의-4대-핵심-기둥-four-pillars"></a>

### OOP의 4대 핵심 기둥 (Four Pillars)

1. **캡슐화 (Encapsulation)**: 데이터와 메서드를 클래스로 묶고, 접근 제어자(`private`)를 통해 외부의 부적절한 직접 접근을 차단함.
1. **상속 (Inheritance)**: 부모 클래스의 자원과 기능을 자식 클래스가 재사용 및 확장함 (`extends`).
1. **다형성 (Polymorphism)**: 하나의 인터페이스나 메서드가 상황에 따라 서로 다른 동작을 수행함 (오버라이딩, 오버로딩).
1. **추상화 (Abstraction)**: 복잡한 내부 구현 세부사항은 숨기고, 필요한 핵심 인터페이스만 외부에 노출함 (`interface`, `abstract`).

<a id="2-java는-왜-객체지향-언어인가"></a>

## 2. Java는 왜 객체지향 언어인가?

Java는 처음부터 객체지향 철학을 바탕으로 설계된 언어다.

1. **클래스 중심 설계 (Class-Centric Design)**:
- Java에서는 클래스 외부에 독립적인 단독 함수나 전역 변수를 작성할 수 없다. 모든 코드와 데이터는 반드시 클래스 내부(`class`)에 존재해야 한다.

1. **4대 객체지향 특징의 완벽한 언어적 보장**:
- `private`, `protected`, `public` 키워드로 **캡슐화**를 강제한다.
- `extends` 키워드로 단일 **상속**을 지원한다.
- `interface`와 `@Override`를 통해 높은 수준의 **다형성과 추상화**를 구현한다.

1. **풍부한 객체지향 오픈소스 생태계**:
- 객체지향 디자인 패턴(Gang of Four)과 SOLID 원칙을 가장 깔끔하게 적용할 수 있는 표준 환경을 제공한다.

## 3. 프로그래밍 패러다임 비교 (POP, OOP, Pascal, FP)

프로그래밍의 역사는 문제 해결 방식에 따라 여러 패러다임으로 진화해 왔다.


```text
[발전 흐름]
절차지향 (POP / C) ──> 구조적 (Pascal) ──> 객체지향 (OOP / Java) ──> 함수형 (FP / Haskell)
```

<a id="1-pop-procedure-oriented-programming-절차지향"></a>

### ① POP (Procedure-Oriented Programming, 절차지향)

- **개념**: 프로그램의 실행 순서(절차)와 **함수(Procedure)** 단위로 코드를 작성하는 방식 (예: C 언어).
- **특징**: 데이터와 함수가 분리되어 있어 프로젝트가 커지면 데이터 변경 시 모든 함수를 수정해야 하는 유지보수 한계가 발생한다.
<a id="2-oop-object-oriented-programming-객체지향"></a>

### ② OOP (Object-Oriented Programming, 객체지향)

- **개념**: **객체(Object)**를 단위로 상태와 행위를 묶어 모듈화하는 방식 (예: Java, C++).
- **특징**: 재사용성, 확장성, 유지보수성이 뛰어나 대규모 엔터프라이즈 시스템 구축의 표준으로 자리 잡았다.
<a id="3-파스칼-프로그래밍-pascal-structured-programming"></a>

### ③ 파스칼 프로그래밍 (Pascal & Structured Programming)

- **개념**: 1970년 닉클라우스 비르트가 만든 언어로, **구조적 프로그래밍(Structured Programming)**의 시초다.
- **특징**: 무분별한 `goto` 문 사용을 금지하고, `begin-end` 블록과 조건문/반복문, 서브루틴을 도입하여 코드의 흐름을 통제 가능한 구조로 만들었다. Modern 언어 제어문의 뿌리가 됨.
<a id="4-fp-functional-programming-함수형-프로그래밍"></a>

### ④ FP (Functional Programming, 함수형 프로그래밍)

- **개념**: **순수 함수(Pure Function)**와 **불변성(Immutability)**을 바탕으로 데이터 변형(Side-effect)을 최소화하는 방식 (예: Haskell, Scala, Modern JS / Java 8+ Stream).
- **특징**: 함수를 1급 객체(First-Class)로 다루며, 멀티스레드 동시성 환경에서 상태 변경 에러가 적어 최근 다시 주목받고 있다.
