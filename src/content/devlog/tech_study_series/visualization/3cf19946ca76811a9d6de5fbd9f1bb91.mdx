## 핵심 요약

색상과 축은 "데이터 값을 화면 값으로 옮기는 규칙"인 스케일의 두 축입니다. 잘못 고르면 없는 패턴을 만들어냅니다. 이 노트는 (1) 팔레트 세 유형(순차형·발산형·범주형)과 접근성, (2) 0 기준선·로그축·이중 축·종횡비라는 축 설계 쟁점을 다룹니다.


<NotionDivider />

<a id="추상화-계층-구분선"></a>

## 추상화 계층 구분선

- <strong>인지·지각 이론</strong>: 색 명도는 정량 인코딩 정확도 하위, 위치·길이는 상위(→ 03 노트).
- <strong>차트 설계 원칙</strong>: 이 노트. "막대는 0에서 시작", "발산형은 중앙 기준값이 있을 때" 같은 규범.
- <strong>도구 구현</strong>: `cmap` 이름, `set_yscale('log')` 등은 도구 노트에 위임.

<NotionDivider />

<a id="1-색상-팔레트-세-유형"></a>

## 1. 색상 팔레트 세 유형

색은 정량 비교에 약하므로(03 노트) <strong>어떤 데이터에 어떤 팔레트를 쓰는가</strong>가 색 설계의 거의 전부입니다.

<a id="11-순차형-sequential"></a>

### 1.1 순차형 (sequential)

- <strong>대상</strong>: 낮음→높음의 순서만 있는 값(인구 밀도, 매출, 확률).
- <strong>구조</strong>: 한 색조에서 명도·채도가 단조롭게 변함(연한 파랑 → 진한 파랑).
- <strong>원칙</strong>: 값의 순서와 밝기의 순서가 일치해야 함. 무지개(jet) 팔레트는 밝기가 비단조라 순서 왜곡·거짓 경계를 만들어 일반적으로 지양합니다. `viridis`, `cividis` 같은 지각 균등(perceptually uniform) 팔레트가 권장됩니다.
<a id="12-발산형-diverging"></a>

### 1.2 발산형 (diverging)

- <strong>대상</strong>: <strong>의미 있는 중앙 기준값</strong>이 있고, 그 위아래로 벌어지는 값(0을 기준으로 한 증감률, 평균 대비 편차, 상관계수 −1~+1).
- <strong>구조</strong>: 중앙은 연한 회색/흰색, 양쪽 끝으로 갈수록 서로 대비되는 두 색조(파랑↔빨강).
- <strong>원칙</strong>: 중앙점을 데이터의 기준값(0, 평균 등)에 <strong>명시적으로 고정</strong>해야 합니다. 중앙을 데이터 중앙값에 자동으로 두면 "기준 대비 증감"이라는 의미가 사라집니다. 기준값이 없는 데이터에 발산형을 쓰면 없는 이분법을 암시합니다.
<a id="13-범주형-qualitative"></a>

### 1.3 범주형 (qualitative)

- <strong>대상</strong>: 순서 없는 명목 범주(지역, 제품군).
- <strong>구조</strong>: 명도는 비슷하고 색조만 다른 구별되는 색들.
- <strong>원칙</strong>: 7~8색 이내(03 노트). 그 이상이면 묶거나 "기타" 처리하거나 facet으로 분리.
<a id="14-접근성"></a>

### 1.4 접근성

- <strong>색각 이상</strong>: 남성의 약 8%가 적록 색각 이상입니다(자주 인용되는 수치). 빨강↔초록 대비만으로 정보를 구분하면 이들에게는 전달되지 않습니다.
- <strong>대책(일반적 권장)</strong>: 색각 안전 팔레트(`viridis`, ColorBrewer의 colorblind-safe 세트) 사용, 색에만 의존하지 말고 <strong>모양·패턴·직접 라벨</strong> 등 이중 인코딩, 흑백 인쇄·복사 상황을 위해 명도 대비 확보.
- 색은 가급적 <strong>보조 채널</strong>로 두고, 주 정보는 위치·길이로 싣습니다.

<a id="2-축과-스케일"></a>

## 2. 축과 스케일

<a id="21-0-기준선"></a>

### 2.1 0 기준선

- <strong>막대그래프: 0에서 시작 필수.</strong> 막대는 길이로 값을 인코딩하므로, 축을 잘라내면(truncated axis) 길이 비율이 실제 값 비율과 달라져 차이를 과장합니다. 이것이 "잘린 축은 막대에서 특히 문제"인 이유입니다.
- <strong>라인 차트: 맥락에 따라.</strong> 라인은 위치와 기울기로 변화를 보여주므로 0을 반드시 포함할 필요는 없습니다. 오히려 좁은 범위 변동을 볼 때는 0을 강제하면 추세가 뭉개집니다. 다만 축이 0에서 멀리 잘려 있으면 그 사실이 드러나게 표시하는 편이 좋습니다.
<a id="22-로그-스케일"></a>

### 2.2 로그 스케일

- <strong>쓸 때</strong>: 값이 여러 자릿수에 걸쳐 있을 때, <strong>배수(곱셈적) 변화</strong>가 관심사일 때(2배 증가가 어디서든 같은 거리로 보임), 지수 성장의 직선화.
- <strong>주의</strong>: 로그축에서 직선은 "일정 증가"가 아니라 "일정 배율"을 뜻합니다. 일반 청중은 오해하기 쉬우므로 설명적 차트에서는 라벨·주석으로 명시합니다. 0과 음수는 표현 불가.
<a id="23-이중-축-dual-axis"></a>

### 2.3 이중 축 (dual axis)

- 왼쪽·오른쪽에 서로 다른 척도를 놓고 두 계열을 겹치는 방식입니다.
- <strong>위험</strong>: 두 축의 스케일·원점을 임의로 맞추면 상관·교차 시점이 자유자재로 조작됩니다. 상관 착시(spurious correlation)를 유발합니다.
- <strong>일반적 대안</strong>: 두 계열을 위아래 패널로 분리(공유 x축), 또는 하나를 지수화/정규화해 한 축에 표시. 이중 축은 대체로 지양이 권장됩니다.
<a id="24-종횡비-aspect-ratio"></a>

### 2.4 종횡비 (aspect ratio)

- 기울기 판단은 선이 화면에서 이루는 각도에 좌우됩니다. Cleveland의 <strong>"banking to 45°"</strong> 는 평균 기울기가 45°에 가깝도록 종횡비를 잡으면 기울기 변화를 가장 잘 읽는다는 경험칙입니다.
- 가로로 심하게 늘이면 변화가 평평해 보이고, 세로로 늘이면 급격해 보입니다. 종횡비를 바꿔 인상을 조작하는 것은 흔한 왜곡 기법입니다(→ 05 노트).

<NotionDivider />

<a id="3-요약-원칙"></a>

## 3. 요약 원칙

- 순서만 있음 → 순차형(지각 균등). 기준값 중심 증감 → 발산형(중앙 고정). 명목 → 범주형(≤8색).
- 색에만 의존 금지, 이중 인코딩.
- 막대는 0부터. 라인은 맥락. 로그는 배수 관심사일 때 + 명시.
- 이중 축 지양. 종횡비는 기울기 판단에 영향.
